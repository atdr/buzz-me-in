# Deploy and operate

**Use this skill when** you ship code to the Pi, the service is down, or you're rebuilding the environment.
**Do NOT use it for**: diagnosing call-flow bugs once the service is up (`intercom-debugging-playbook`), local development (`intercom-testing-and-validation`), or general cloudflared configuration facts — ingress rule semantics, Access wiring, service-install gotchas — which live in `cloudflared-tunnels`.

README's Setup section (steps 1–6) is the doc of record for from-scratch installation. This skill assumes it exists and adds what README doesn't: day-2 operations.

## The deployment model

Two systemd units, journald logging, `.env` file for config. Throughout, `pi@raspberrypi.local`, `User=pi` and `/home/pi/intercom` are Raspberry Pi OS defaults used as examples, not a description of any particular host.

- `intercom.service` — `ExecStart=/usr/bin/env buzz-me-in`, `User=pi`, `WorkingDirectory=/home/pi/intercom`, `EnvironmentFile=/home/pi/intercom/.env`. `Restart=on-failure` with `RestartSec=5`: crashes restart in ~5 s, **clean exits stay down** (intentional, so a deliberate stop sticks). Ordered `After=cloudflared.service`. The code comes from a global npm install (`npm prefix -g`), the config and pairing state from `WorkingDirectory`; npm never touches the latter.
- `cloudflared.service` — generated by `sudo cloudflared --config ~/.cloudflared/config.yml service install` (README step 6), reading `/etc/cloudflared/config.yml`. Tunnel config edits go in that file, then `sudo systemctl restart cloudflared`.

The server exits deliberately on `uncaughtException`/`unhandledRejection` and relies on systemd to restart it — a restart in the journal is the designed recovery path, not necessarily a bug to chase (but grep the exception first).

## Ship a change

Shipping means publishing a release, then installing it. Merging the release-please PR tags the release and publishes to npm; nothing then upgrades the Pi automatically.

```bash
# After the release PR merges and the version is on npm:
ssh pi@raspberrypi.local 'sudo npm install -g buzz-me-in@latest && sudo systemctl restart intercom'

# Confirm:
ssh pi@raspberrypi.local 'systemctl is-active intercom cloudflared'
ssh pi@raspberrypi.local 'npm ls -g --depth=0 buzz-me-in'   # confirms the version actually installed
curl https://$TUNNEL_HOSTNAME/healthz   # expect {"ok":true}
```

**203/EXEC on start** means `buzz-me-in` is not on systemd's PATH. `ExecStart` resolves it via `/usr/bin/env` precisely so the unit works under both common npm prefixes (`/usr/local` for Debian's apt nodejs, `/usr` for NodeSource), so this points at an unusual prefix such as nvm rather than at a wrong hardcoded path. Check `npm prefix -g` against `systemctl show intercom -p ExecStart` and the unit's PATH.

After any deploy that touched the call path, run the relevant README E2E stages (see `intercom-testing-and-validation` for the mapping) — one planned test call.

## Operational field guide

```bash
# Live logs (JSON lines):
journalctl -u intercom -f -o cat
journalctl -u cloudflared -f -o cat

# Everything since last boot:
journalctl -u intercom -b -o cat

# Is a call active right now?
curl -H "Authorization: Bearer $STATUS_API_TOKEN" https://$TUNNEL_HOSTNAME/status
# → {"active":false} or {"active":true,"callSid":"CA…"}

# Service control:
sudo systemctl restart intercom          # safe when no call active (check /status first)
sudo systemctl status intercom cloudflared
```

Notes:

- **Restarting drops the in-memory nonce store** — a caller who dialed during the restart window gets one failed connection (token verification fails). Check `/status` before restarting.
- **Stale sessions self-heal**: a dead call's slot is reaped after `CALL_SESSION_STALE_SEC` (default 900 s). Restarting clears it immediately.
- **HAP pairing data lives in `persist/` under the working directory** (`/home/pi/intercom/persist` — HAP-NodeJS stores it via node-persist, which resolves the directory relative to the process cwd; it is listed in `.gitignore` and `.prettierignore`). Restarts do NOT require re-pairing. Changing `HAP_USERNAME` effectively creates a new accessory and DOES require re-pairing.
- **The working directory is deliberately outside anything npm manages.** `sudo npm install -g buzz-me-in` writes only under `npm prefix -g`, so an upgrade cannot touch `.env` or `persist/`. Nothing in the deploy path deletes them, but copy `persist/` somewhere safe before any invasive work on the Pi.

## Outage discrimination (fastest split first)

| Test                                                                     | Result | Conclusion                                                                                                                           |
| ------------------------------------------------------------------------ | ------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| On the Pi: `curl localhost:8080/healthz`                                 | fails  | Server down → `journalctl -u intercom -b -o cat`, look for `[config]` (bad env → crash-loop), `uncaught-exception`, or port conflict |
| Server OK locally, `curl https://$TUNNEL_HOSTNAME/healthz` from anywhere | fails  | Tunnel down → `journalctl -u cloudflared`, `cloudflared tunnel info intercom`                                                        |
| Both OK but calls don't arrive                                           | —      | Twilio side → console → Phone Numbers → Voice webhook must be `https://{host}/twiml`, POST; check Twilio call log for webhook errors |
| Calls arrive but misbehave                                               | —      | → `intercom-debugging-playbook`                                                                                                      |

## From-scratch rebuild checklist (delta over README)

README steps 1–6 are complete and current. Additional hard-won specifics:

- ffmpeg must have **both** libx264 and libopus: `ffmpeg -codecs | grep -E "libx264|libopus"` — the stock `apt install ffmpeg` on Raspberry Pi OS includes both.
- `HAP_PORT` (default 47129) and mDNS (UDP 5353, Avahi) must be reachable from the iPhone's LAN — HomeKit discovery is LAN-multicast; the tunnel plays no part in HomeKit traffic.
- Generate `HAP_USERNAME` and `HAP_PINCODE` with the one-liners in `.env.example` comments; both are format-validated at startup.
- systemd unit paths assume `/home/pi/intercom` — edit `WorkingDirectory`/`EnvironmentFile`/`User` if different. `ExecStart` needs no edit: it resolves `buzz-me-in` from systemd's PATH (`/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin`), which covers both common npm prefixes.
